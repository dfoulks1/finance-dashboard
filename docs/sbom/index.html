Software Bill of Materials (SBOM)¶

A living inventory of every third-party dependency this project ships or builds with, plus its license. This matters for two reasons:

  1. ASF 3rd-party licensing policy — every dependency must be compatible with Apache-2.0 per the 3rd Party Licensing Policy. Category X licenses must not be included; Category B has conditions.
  2. AI provenance — AI-generated code can silently pull in dependencies. Tracking them here is part of satisfying Contribution Guide §3.2 (no unexpected third-party material, or compatibly licensed and disclosed).

Scope today

The application is not built yet, so the only actual dependencies are the documentation toolchain. The runtime rows are the planned stack and are marked accordingly — they become real (with pinned versions) as the numbered prompts implement them.

Documentation toolchain (in use)¶

Component Version License Category Purpose
mkdocs >=1.6 BSD-2-Clause A Static docs site generator
pymdown-extensions >=10.0 MIT A Markdown extensions (snippets, superfences, mermaid)

The docs use a custom MkDocs theme built on Bootstrap 5 (in theme/, Jinja2 templates — matching the dashboard's own stack), not a third-party theme package. These front-end assets load client-side from a CDN at page-view time (not build dependencies):

Category refers to the ASF classification: A = compatible, B = allowed with conditions, X = prohibited. Confirm each row against the policy before a dependency lands; do not treat this table as a legal sign-off.

Keeping this current¶

  • Pin exact versions in pyproject.toml / docs/requirements.txt when a dependency becomes real, then reflect them here.
  • When the app exists, generate a machine-readable SBOM in CI — e.g. CycloneDX via cyclonedx-py — and link the artifact from this page. A generated SBOM supplements, but does not replace, the human license-category review required by ASF policy.
  • Any dependency introduced by AI-generated code must be added here as part of the same PR (Contribution Guide checklist).
